# Ingress host → Deployment map (`infra/k8s`, `infra/helm`)

Generated by static analysis of every `Ingress`, `Service` and `Deployment`
manifest in `infra/k8s`, joined Service-selector → Deployment-pod-labels →
container. Nothing here was read from a live cluster.

"Serves" is derived from the container itself, not from its name:

- **frontend** — the container runs the app's Next.js server (`next start`
  via the app's `Dockerfile`), identified by an `/api/health` HTTP probe and an
  image with no `-backend` suffix.
- **backend** — the container runs the Fastify server, identified by a
  `-backend` ECR repository (built from `Dockerfile.backend`) and `/readyz` +
  `/livez` probes, or by an explicit `tsx backend/server.ts` command override.

### Notes on the rows that do not resolve inside `infra/k8s`

- **`quant-production` `quant-platform-production-*` Services** are rendered by
  the Helm chart (`infra/helm/quant-platform`, release `quant-platform-production`),
  not by `infra/k8s`. They are not missing; see the Helm section below.
  `infra/k8s/app-routing-ingress.yaml` and `infra/k8s/quantmail-backend.yaml`
  attach extra hosts and the `/api` rewrite to those Helm-owned Services.
- **`quant-staging` → `quant-quantmail-backend:3011`** (4 host rules in
  `staging-api-ingress.yaml`) has **no Service or Deployment manifest anywhere in
  the repo**. The only `quant-quantmail-backend` manifest
  (`infra/k8s/quantmail-backend.yaml`) is named
  `quant-platform-production-quantmail-backend` and lives in `quant-production`.
  The staging object was created imperatively and is undeclared. Tracked as a gap,
  not changed here.
- **`*.quant.ecosystem`** (`ingress-quantmail.yaml`, `ingress-quantchat.yaml`,
  `ingress-quantai.yaml`) target Services `quantmail` / `quantchat` / `quantai`
  on port 80 in the `default` namespace. No such Service or Deployment exists in
  the repo, the hostnames are not real DNS, and nothing else references them.
  These are dead manifests from an early bring-up.

## Conclusion

Every host that resolves to a Deployment already has one. **There is no ingress
host in `infra/k8s` or `infra/helm` whose frontend Deployment is missing** —
including `quantube`, `quantmax`, `quantneon` (`quantgram`) and `quantedits`
(`quantcooks`), all four of which have a frontend Deployment, Service and
Ingress rule in `infra/k8s/staging-remaining-apps.yaml`.
