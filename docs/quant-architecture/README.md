# Quant Architecture — Company-Scale Blueprint

Status: Architecture V1.

This directory is the executable architecture map for Quant. GOAL.md defines the north star; this directory defines ownership, system boundaries, contracts, screens, backend surfaces, engines, platform targets and build order.

Canonical products: QuantMail, QuantChat, QuantAI, QuantGram, QuantWave, QuanTube, QuantMax, QuantCooks, QuantAds. QuantTrinity is the economy control-plane, not a tenth consumer product.

Read in order: 00-architecture-charter, 01-system-topology, 02-company-and-admin-model, 03-product-boundaries-and-domains, 04-platform-client-architecture, 05-data-and-event-architecture, 06-ai-quanty-platform, 07-algorithm-platform, 08-identity-security-trust, 09-economy-billing, 10-reliability-observability, 11-contracts, 12-screen-inventory, 13-backend-inventory, 14-build-order, 15-definition-of-done, 16-repository-target-tree, 17-screen-spec-template, 18-backend-spec-template, 19-execution-system, 20-ecosystem-cross-app-connection-contract.

Core law: nine independent products, one platform, one governed identity system, one economic ledger, one intelligence/agent layer, product-owned administration and platform-owned primitives.

A route, mock, screenshot or successful API response never proves completion. Completion requires real data, permissions, errors, loading/empty states, observability, tests and live platform verification.
