# 14 — Build Order

We build in dependency order, not excitement order.

Phase 0: architecture truth — canonical names, ownership, contracts, source-of-truth map, mock/fallback audit and platform matrix.

Phase 1: platform kernel — identity, authorization, app registry, brand tokens, API contracts, event envelope/outbox, audit, flags, observability.

Phase 2: QuantMail reference — shell, inbox, thread, compose, search, contacts, calendar, drive, Git, universal search, Quanty, security, admin and mobile/native parity.

Phase 3: Quanty core — model gateway, context manager, memory, tools, planner, executor, approvals, budgets, verification, audit and evaluation.

Phase 4: cross-product backbone — events, knowledge graph, universal search, notifications, shared signals and trust/safety.

Phase 5: QuantChat — realtime, delivery, calls, notifications and moderation.

Phase 6: QuantGram + QuantWave — social graph, feed/ranking, moderation and creator foundations.

Phase 7: QuanTube + QuantCooks — media pipeline, transcoding, editing and creator economy.

Phase 8: QuantMax — discovery/matching after trust, safety and realtime foundations are proven.

Phase 9: QuantAds + economy scale — auction, attribution, fraud, payouts and advertiser workflows.

Phase 10: native platform parity — web, Android, iOS and desktop verification.

Phase 11: scale — service extraction, sharding, multi-region, GPU infrastructure and global optimization.

Do not advance because code exists. Advance only when contracts, backend, UI, tests, security, observability, platform verification and production-safety evidence exist.
