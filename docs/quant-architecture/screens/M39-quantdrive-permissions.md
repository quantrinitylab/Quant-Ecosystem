# M39 — QuantDrive Permission UX

## Access model presentation
Show who has access, their permission level, inherited access where applicable, link audience, expiry, and relevant organization policy.

## Proposed vs current
The UI must separate current authoritative access from unsaved proposed changes. A user should be able to cancel without ambiguity.

## Permission failures
Explain whether the user lacks access, the object is unavailable, the organization policy blocks the action, or the operation is pending.

## Cross-product rule
Opening a file from Mail, Calendar, Contacts, or Git does not grant extra Drive permission. Context links are not authorization tokens.
