# 17 — Screen Specification Template

Every production screen receives one file.

## Identity
Screen ID, product, route/deep link, owner, status, dependencies, milestone.

## User goal
What decision/action should the user accomplish?

## Information architecture
Every region, hierarchy and priority.

## Component contract
Purpose, inputs, outputs, states, interactions, accessibility and analytics.

## State matrix
Initial, loading, populated, empty, partial, error, offline, permission denied, stale, reconnecting, destructive confirmation.

## Data
Queries/commands, schemas, cache, pagination, optimistic behavior and invalidation.

## Security
Auth, authorization, sensitive data, redaction and audit.

## Quanty
Available tools, context, risk, approval, cost, verification and undo.

## Responsive
Web desktop, web mobile, Android, iOS, Windows, macOS, Linux.

## Performance
Initial render, interaction latency, requests, media and memory budgets.

## Testing
Unit, integration, visual, accessibility, E2E and device matrix.

## Evidence
Implementation commit, test results and live verification references.
